00 / OVERVIEW

서비스와 개선 방향

사용자가 제보한 지역별 재난 정보를 공유하는 서비스입니다. 6인 팀에서 Backend·Infra를 맡았고, 이후 개인 고도화 과정에서 부하 테스트로 병목을 확인하고 컴퓨트 아키텍처와 배포 방식을 개선했습니다.

부하 테스트로 병목을 찾고, 캐시·비동기 처리와 실행 환경 전환을 통해 성능과 배포 흐름을 개선했습니다.
01 / PERFORMANCE

측정으로 병목을 찾고 처리 방식을 나누기

부하 테스트로 병목 구간을 식별한 뒤 Redis 캐싱과 Celery 비동기 큐를 적용했습니다.

02 / COMPUTE ARCHITECTURE

단일 노드의 자원 제약 분석과 아키텍처 전환

메모리와 I/O 지표를 바탕으로 단일 노드 k3s의 자원 제약을 분석하고, 컴퓨트 아키텍처를 ECS Fargate로 전환했습니다.

사용한 구성

  • AWS ECS Fargate · RDS · EC2
  • Django · PostgreSQL · Redis · Celery
  • Terraform 기반 인프라 코드화
03 / DELIVERY AUTOMATION

인프라와 배포를 코드로 관리하기

Terraform으로 인프라를 코드화하고 GitHub Actions에 OIDC를 적용했습니다. 이를 기반으로 무중단 배포를 자동화했습니다.
